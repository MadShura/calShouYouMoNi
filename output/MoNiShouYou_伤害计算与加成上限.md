## 1. 一次攻击的完整伤害链路

普攻和技能共用同一套结算（`Action_CommonAttack.Excute` / `Action_Skill.Excute`）：

```text
1. 构造 Damage_Recorder，BaseAttack = 攻击者最终攻击力
   ActionData.cs 第 37 行：BaseAttack = GetFinalValue(ATK)

2. 命中判定（MingZhong_Recorder.cs 第 19-21 行）
   命中值 = 100 + 攻击者命中 - 目标闪避 + 加成
   命中率 = clamp((命中值 + 1) / 101)      // Random.Range(0,101) <= 命中值
   未命中 → 伤害为 0，显示 Miss

3. 暴击判定（BaoJiRecorder.cs 第 19-21 行）
   暴击值 = 攻击者暴击 - 目标抗暴 + 加成
   暴击率 = clamp((暴击值 + 1) / 101)

4. 最终伤害（Damage_Recorder.cs 第 55-110 行 CulFinalDamage）

   DEF_eff = max(1, 目标防御 - 攻击者穿透)
   K = CulDamagePercent(ATK, DEF_eff)                  // 见第 2 节
   基础 = ATK × K / 100                                 // 至少 1
   基础 ×= Random(0.95, 1.05)
   伤害 = 基础 × Π(100 + p_i) / 100                     // 所有百分比加成的连乘
   若暴击：伤害 ×= 暴击伤害 / 100
   伤害 ×= (100 + 伤害加成) / 100
   伤害 ×= (100 - min(目标伤害减免, 80)) / 100
   伤害 = max(1, 伤害)
```

要点：

- `PercentAddition` 是一个列表，**每个来源各自乘一次**，不是加在一起。所以 3 个 +50% 是 ×1.5×1.5×1.5，不是 ×2.5。
- 技能伤害不是固定倍率：技能同样以攻击力为基底，通过 Entry 往 `PercentAddition` 里塞百分比。
- 普攻/技能都是 `BaseAttack = 最终攻击力`，所以**攻击力是唯一的基础伤害来源**。

## 2. 攻防比系数 `CulDamagePercent`（Damage_Recorder.cs 第 138-161 行）

```text
DEF_eff <= 0        → 100
ATK == DEF_eff      → 50
ATK >= 3 × DEF_eff  → 100
ATK × 3 <= DEF_eff  → 2
ATK > DEF_eff       → 50 + (ATK - DEF_eff) × 50 / DEF_eff × 2
ATK < DEF_eff       → 2 + (ATK × 3 - DEF_eff) × 48 / (DEF_eff × 2)
```

关键结论：

- 系数区间是 **2 ~ 约 248**，不是 0~100。
  - `ATK = 2 × DEF` 时：`50 + (DEF)×50/DEF×2 = 150`
  - `ATK → 3 × DEF` 时：系数趋近 250
- **`ATK >= 3 × DEF_eff` 时会被硬切成 100**，从约 250 掉回 100，这是一处明显的分段不连续（代码缺陷）。
- 所以「攻击力越高越好」并不绝对：刚好卡在 3 倍防御附近会掉档。
- 穿透的作用就是降低 `DEF_eff`，把系数往上抬；一旦 `ATK >= 3 × (DEF - 穿透)`，再堆穿透对这一次攻击的系数毫无收益。

## 3. 每个属性对伤害的真实作用

| 属性 | 进入伤害的方式 | 是否有上限 |
| --- | --- | --- |
| 攻击 ATK | 唯一基础伤害 | 无硬上限（BigInteger） |
| 穿透 | 先减目标防御，再走攻防比系数 | 收益在 `ATK >= 3×DEF_eff` 后归零 |
| 防御 | 只影响被打时的 `DEF_eff` | 无 |
| 暴击 | 暴击率 =（暴击-目标抗暴+加成+1)/101 | 实际 100%，超过即溢出 |
| 抗暴 | 降低对方暴击率 | 同上 |
| 暴击伤害 | 暴击时 ×暴伤/100 | 无硬上限 |
| 伤害加成 | ×(100+值)/100 | 无硬上限 |
| 伤害减免 | ×(100-min(值,80))/100 | **封顶 80** |
| 命中 | 命中率 =（100+命中-目标闪避+加成+1)/101；**命中率封顶后，命中值仍会通过西行取经、神通 3、技能 78 转成伤害%** | 命中率 100%，但作为伤害系数时无上限 |
| 闪避 | 降低对方命中率；**神鬼志异羁绊会用（闪避-敌命中）转伤害%** | 命中率部分 100%，转伤害部分无上限 |
| 连击 | 额外一次攻击的概率 =（连击+1)/101 | 实际 100% |
| 反击 | 被普攻后反击的概率 =（反击+1)/101 | 实际 100% |
| 速度 | 只决定出手顺序（Battle_Action_Manager 第 81 行按 Speed 排序） | 无；但阵法 8 会把速度差换成伤害% |
| 生命 | 不影响输出，只影响存活与阵法 7 | 无 |
| 吸血/反弹/恢复/幸运 | 各自独立结算 | 见对应 Recorder |

补充：

- 每回合每人只有 1 次行动（`ActionCount = 1`），速度不增加行动次数，只决定谁先手。
- 连击是「额外一次完整攻击」，会重新走命中/暴击判定。
- 反击只在对方使用**普攻**时触发（`Battle_Character_Info` 第 214-217 行）。

## 4. 百分比属性的“上限”到底在哪

### 4.1 不是 21 亿：属性面板本身没有 21 亿上限

- `BattleData_Recorder.Base_Value` 是 `double`，`PercentAddition` 是 `long`，`GetFinal` 返回 `BigInteger`（BattleData_Recorder.cs 第 7-35 行）。
- 所以攻击、穿透、暴击等属性值本身可以远超 21 亿。

### 4.2 21 亿来自 int 转换处的夹取

| 位置 | 上限 | 说明 |
| --- | --- | --- |
| `Entry_ZhenFa_8.WhenAttack_Cul_1` | 2,147,483,646 | 速度差转伤害%，超过后夹到 21 亿 |
| `Entry_ShenTong_3.WhenAttack_Cul_1` | 2,147,483,637 | 命中×Base×等级/10 转伤害%，超过夹取 |
| `Damage_Recorder.CulFinalDamage` | 9,223,372,036,854,775,806 | 百分比连乘结果转 long 溢出时取这个值 |
| `NumsHelper.ToMax(int)` | 2,040,109,440 | 通用 int 夹取（约 20.4 亿） |
| `NumsHelper.ToMax_1(long)` | 9,223,372,036,854,775,806 | 通用 long 夹取 |
| `NumsHelper.ToMax(long)` | 8,762,203,325,060,874,240 | 另一套 long 夹取 |

结论：**“21 亿”不是游戏设定的伤害上限，而是 `int` 能装下的最大值**。真正会挡住你的上限是下面这些。

### 4.3 真正影响输出的硬上限

1. **伤害减免 80%**（Damage_Recorder.cs 第 88-92 行）
2. **攻防比系数 100（3 倍防御）/ 2（3 倍攻击被压制）**，且 3 倍处有不连续掉档
3. **命中率/暴击率/连击率/反击率 100%**（判定是 `Random(0,101)`，值 ≥ 101 后无收益）
4. **伤害百分比单来源 21 亿**（阵法 8、神通 3）
5. **伤害百分比连乘 long 上限 9.22e18**
6. **SP 上限 101**（神通 6 可 +100 → 201），神通 6 的伤害% 依赖 SP

## 5. 阵法对伤害的加成

阵法数据在 `StreamingAssets/ZhenFa_Data_Json.txt`，每个阵法有两部分：

- `EffectNameEnum 0`（ChangeBattleProperty）：直接加属性
- `EffectNameEnum 1`（EntryEffect）：挂一个战斗 Entry

当前存档佩戴的是 **1 号阵，等级 246**。

| 阵法 | 属性加成（来自配置） | Entry 效果 | 对输出的意义 |
| --- | --- | --- | --- |
| 1 | 攻击 +15% | `Entry_ZhenFa_1`：**全场攻击最高的单位，攻击力再 + 阵法等级%** | 246 级 = 最高攻单位 +246% 攻击，极强 |
| 2 | 反弹伤害 +15% | `Entry_ZhenFa_2`：降低敌方反弹 8，并给自己挂 `ZhenFa_2_1` | 防御向 |
| 3 | 闪避 +15% | `Entry_ZhenFa_3`：未命中时给自己 +命中（持续 2 回合） | 补命中 |
| 4 | 连击 +10%、反击 +10% | `Entry_ZhenFa_4`：连击动作伤害 +连击×10%；反击动作伤害 +反击×10% | 连击/反击流核心 |
| 5 | 生命 +20% | `Entry_ZhenFa_5`：非暴击时受到伤害 -40% | 防御向 |
| 6 | 暴击 +20% | `Entry_ZhenFa_6`：暴击值 +30；暴击时伤害 +暴击×10% | 暴击流核心，暴击点数双重收益 |
| 7 | 生命 +30% | `Entry_ZhenFa_7`：全场生命最高单位再 + 阵法等级% 生命 | 防御向 |
| 8 | 速度 +15 | `Entry_ZhenFa_8`：伤害% +=（我方速度 - 对方速度），上限 21 亿 | 速度差直接变伤害，速度成为输出属性 |
| 9 | 幸运 +50% | `Entry_ZhenFa_9`：命中时 25% 概率额外掉一件道具 | 收益向 |

重点：

- **阵法 1 的加成不在属性面板里**，是战斗开始时给最高攻单位额外加 `ATK × 等级%` 的平攻击。所以「阵法升级」的实际收益远大于面板上的 +35 攻击/穿透。
- **阵法 8 把速度差变成伤害百分比**，且上限是 21 亿。速度不再只是先手。
- **阵法 6 让暴击点数变成双重收益**：既加暴击率，又在暴击时加`暴击×10%`伤害。

| 神通 | 条件 | 伤害加成 | 上限 |
| --- | --- | --- | --- |

## 8. 主角属性如何进入英灵伤害

`Battle_Character_Info.Initailharacter`（第 41-55 行）→ `BattleData_Manager.InitailForBattle`：

```text
每个英灵的战斗属性 =
  非百分比属性：(英灵自身 Base + 主角 Base) × (100 + 英灵百分比 + 主角百分比) / 100
  百分比属性：  英灵自身 Base + 主角 Base
```

（`BattleData_Manager.GetFinalValue` 第 74-85 行 + `BattleData_Recorder.GetFinal` 第 23-35 行）

结论：

- **主角的攻击、穿透、防御、生命会同时加给所有上阵英灵**；主角的百分比加成也会叠加到英灵身上。
- 主角的暴击/暴伤/命中这类百分比属性是**直接加到每个英灵的绝对值上**（不是乘）。
- 所以：
  - 装备强化、阵法、圣兽、图鉴、制作装备（都加主角）→ 全队受益。
  - 转职强化只加单个英灵。

## 9. 百分比 vs 加法：正确的性价比算法

把「输出」统一成**期望伤害**，而不是属性点：

```text
D = ATK × K / 100
    × 命中率
    × (1 + 暴击率 × (暴伤/100 - 1))
    × (1 + 伤害加成/100)
    × (1 - min(目标减伤, 80)/100)
```

单点属性的边际收益（当前值下）：

| 提升 | 伤害变化 |
| --- | --- |
| +1 攻击 | +1 / ATK（K 不变时）；在 1~3 倍防御区间内可到 2 / ATK |
| +1 穿透 | 抬高 K；`ATK >= 3×DEF_eff` 后为 0 |
| +1 暴击 | +(1/101) × (暴伤/100 - 1)（未溢出时）≈ 0.4%（暴伤 140 时） |
| +1 暴伤 | +暴击率 × 1% ≈ 0.4%~0.5% |
| +1 命中 | 命中率未满时 +1/101；已满时为 0 |
| +1 伤害加成 | +1% |
| +1 速度 | 只影响先手；阵法 8 下 +1% 伤害（速度差） |
| +1 连击 | +1% 概率额外一次完整攻击 |

用当前存档（Save_1）实测代入：

- 最高输出单位：英灵 1147（主角继承后攻击 13.2 亿、穿透 11 亿、暴击 111、暴伤 330、命中 113、伤害加成 33%）
- 佩戴阵法 1（Lv.246）→ 战斗开始最高攻单位再 +246% 攻击
- **命中 113、暴击 111 已经超过 100% 上限**，所以：
  - 蟠桃（+1 命中）、东海仙枣（+1 暴击）收益 **0**
  - 只有南海仙荔（+1 暴伤）有收益：约 **+0.303% 伤害**，价格 52,888 元宝 → **5.7e-6 %伤害/元宝**
- 1 个寒铁卖 0.000167 元宝；用于制作装备期望 **+0.055% 伤害/个**（炼器 360 级、器鼎 378 级）
- 按材料比：制作路线是「卖材料换药」的 **约 10^8 倍**

结论不变，但原因要说清楚：**药是百分比，收益约 0.3%/颗；材料强化给的是几千到几万点攻击，按当前攻击基数折算同样是小比例，但材料几乎不要钱（元宝计价极低），所以直接强化碾压卖材料换药。**

注意：暴击/命中是否溢出取决于目标抗暴/闪避。脚本默认目标抗暴=0，实际打有抗暴的敌人时请用 `--target-resist=30` 之类的参数重算。

## 11. 属性超过 100% 之后的二次利用

命中率/暴击率/连击率/反击率封顶 100% 不代表这些属性没用了，代码里有专门的「属性转伤害」入口：

| 属性 | 二次利用 | 代码 |
| --- | --- | --- |
| 命中 | 伤害% +=（命中 − 敌闪避）×（0.25+0.25×等级） | `Entry_XiXingQuJing.cs`（西行取经羁绊） |
| 命中 | 伤害% += 命中 × Base × 等级 / 10，上限 21 亿 | `Entry_ShenTong_3.cs`（神通 3） |
| 命中 | 伤害% +=（命中 − 敌闪避）相关 | `Entry_Skill_78.cs` |
| 闪避 | 伤害% +=（闪避 − 敌命中）×（0.2+0.2×等级） | `Entry_ShenGuiZhiYi.cs`（神鬼志异羁绊） |
| 闪避 | 伤害% += 闪避 × Base × 等级 / 10 | `Entry_ShenTong_8.cs` / `Entry_ShenTong_4.cs` |
| 暴击 | 暴击时伤害 ×（1 + 暴击×10%） | `Entry_ZhenFa_6.cs`（阵法 6） |
| 幸运 | 战斗开始：命中 += 幸运/100×5 | `Entry_Skill_1051.cs`（孙悟空神形态） |
| 速度 | 伤害% +=（我方速度 − 敌方速度） | `Entry_ZhenFa_8.cs`（阵法 8） |

所以「命中 113」在只堆命中率时是浪费，但在**西行取经/神通 3** 体系里仍然 1:1 换伤害。脚本现在会按当前阵型自动识别羁绊，把这一部分算进去。

## 12. 羁绊系统

- 每个英灵有 2 个羁绊类型（`YingLing_SettingData.ZhenRongJiBanTypeEnum`）
- 阵型里同类型人数达到 2/3/4/5 → 羁绊等级 1/2/3/4（`ZhenRong_JiBan.TrrigerEffect`）
- 羁绊效果是 `EntryEffect`，战斗开始时挂到**我方每个单位**身上（`Battle_Character.TrrigerEffect`）
- 12 种羁绊里直接加伤害的只有 5 个：

| 羁绊 | 公式 | 备注 |
| --- | --- | --- |
| 西行取经 | 伤害% +=（命中 − 敌闪避）×（0.25+0.25×等级） | 当前最强，Lv.3 系数 1.0 |
| 神鬼志异 | 伤害% +=（闪避 − 敌命中）×（0.2+0.2×等级） | 需要闪避高于敌命中，否则 0 |
| 万人敌 | 伤害% += 等级 × 敌方存活人数 | 与西行抢位置 |
| 神谋鬼算 | 暴伤 +20×等级 | 暴击率越高越强 |
| 三国群英 | 伤害% +=（100 − 目标血量%）/(4 − 0.5×等级) | 满血首击 0，残血收尾才有收益 |

用当前存档（阵型 [6,26,27,28,29] = 武松/孙悟空/唐三藏/猪八戒/沙僧）跑 `jiban-value.ts`：

- 西行取经 ×4 → Lv.3 → **×1.83**（命中 113 − 敌闪避 30 = 83）
- 神鬼志异 ×3 → Lv.2 → **0**（闪避 98 < 敌命中 100）
- 结论：**「西」是核心，「神」目前完全没生效**；想让神鬼志异有收益，需要闪避 > 敌命中，之后每点闪避约 +0.6%~0.8% 伤害
- 全 118755 种组合里最高就是 ×1.830，当前阵型并列前 6（第 5 个位置随便放都不影响，因为西行最高只到 4 人档）
